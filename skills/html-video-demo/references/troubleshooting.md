# 字尾回归与常见失败

## 尾字还没说完就结束

先定位层次：原始合成 WAV 是否完整；归一化有无缩短；字幕是否过早；拼接和 MP4 音轨是否一致。增加黑场只能调整节奏，无法补回已经被丢掉的音节。

在一个已复现的 MLX Audio 0.6.4 / Qwen3-12Hz 非流式路径中，有效输出长度按 `count(primary_code > 0) × upsample_rate` 计算。生成序列没有 padding，编号 `0` 却是合法码本值；解码器已经生成完整波形，调用方按偏短长度裁掉了尾部。

一次同参数复现中，四个合法零编号导致丢失 0.32 秒，一个导致丢失 0.08 秒；保留下来的波形前缀与原输出逐采样相同。这说明故障位于长度裁剪，而不是简单的转场延迟。数字是诊断案例，不是每个音频都固定丢失这么长。

`qwen_decode.py` 在内存中用含合法零编号的小序列探测该行为。若原生解码已返回完整长度，不安装适配器；若观测到已知错误形态，才为本模型实例安装单条无 padding 解码路径。若形态不同，停止并检查。它不修改第三方安装目录，也不适用于带 padding 的任意 batch、其他 tokenizer 或未知模型架构。

修复后至少核对：

- 有效 codec 帧没有因为编号 0 丢失。
- 字尾自然结束；必要时与裁剪前的波形比较。
- 原始语音样本在切章过程中完整保留。
- 最终 MP4 在切幕位置已收声。

## 同一音色听起来像多个人

先检查是否逐句生成、不断改变随机种子、每段单独改提示词或单独增益归一化。使用固定音色和风格，合并相邻语义段落，控制随机性，并对整轨做一次响度处理。语气仍要试听；同一 speaker ID 不代表每次合成的韵律必然相同。

不要把“整篇一次生成”当作万能修复。长输入可能重复或不结束；改成较短的连续讲述组，并核对内容。也不要把一次成功的组数当作固定模板。

## 长文本触发上限

不输出该次音频为成功结果。缩短出问题的组、检查数字和术语读法、保留其他已验证组。最多做少量有原因的尝试；没有改善时保留日志和可用结果，说明具体限制，切换已授权的替代方案。

## 字幕看似齐了，实际漏读

强制对齐是给定原稿找时间，可能把未说出的字也放进时间轴。用独立 ASR 检查漏句和重复，再听可疑区间。不要把同音字的机器识别差异当成必然发音错误，也不要把高字符串相似度当成自然度评分。

## 画面开头闪过或结尾不够

检查 HTML 是否在字体加载前就开始动画。使用 `__hvPlayAll()` 启动，把明确的时长传给 html-video。转场根据最终配音重新计算；有实际录像时，给录像保留足够播放时间。最后检查 MP4 的音轨和画面，不只看计划里的秒数。

## 版本更新后出错

先记录 html-video commit、MLX Audio 版本、模型 revision 和生成配置。验证版本差异与接口变化后再修改适配器；不要为了通过测试删除结束检查或扩大裁剪范围。保留已通过的旧版成片，生成新的版本目录供比较。
