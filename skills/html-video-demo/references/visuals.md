# 真实素材与 HTML 分镜

## 界面采集

使用演示数据和隔离的工作区。先确认截图中的功能真正可用，再展示点击、拖动、保存或结果变化。不要用一张重画的界面冒充实际运行结果；示意图可以使用，但要与真实操作区别清楚。

通用静态截图：

```sh
node "$SKILL_DIR/scripts/capture.mjs" \
  --project "$DEMO_PROJECT" \
  --url http://127.0.0.1:3000/ \
  --selector main \
  --output assets/overview.png
```

具体交互由当前 Agent 可用、获授权的浏览器工具完成。测试和演示应保留真实用户修改，避免为了截图重置生产状态。处理人脸、账号、消息、内部地址和路径等敏感信息后再导入素材。

录制需要鼠标轨迹时，先验证操作成功，再录制。无头浏览器录像通常不显示系统鼠标，可用页面内指针覆盖层展示真实鼠标事件；不要添加与实际操作不符的虚假成功状态。

## 视觉原则

先表达清楚任务、输入输出与操作结果，再决定构图。用户已有风格优先；默认可以采用克制的技术解说风格，保持字体、强调色和卡片关系一致。不要把每句旁白都复制成满屏说明文字。

真实界面过小时，使用局部放大或前后对照；不要依赖 1080p 截图里十几个像素的小字承载关键结论。每幕保留一个主要信息，辅助说明放字幕或旁白。

本包模板支持标题、步骤、图片、录像、代码。复杂产品演示可直接修改 `compose.mjs` 或替换生成的 HTML，但保留下面的时间协议，并重新执行画面检查。

## html-video 时间协议

- 每幕 HTML 自包含，内联 CSS/JS，将媒体嵌入或保持确定的本地引用；避免渲染时临时拉取 CDN 字体和在线图片。
- `window.__hvPlayAll()` 从零启动动画。html-video 会在页面和字体准备后调用它。
- `window.seek(seconds)` 暂停并定位当前幕，供抽帧检查。
- 在渲染加载阶段不要自动启动定时器或 CSS 动画，否则可能把开场动画录在被裁掉的加载等待中。
- 视频的 `currentTime` 和触发时刻必须与幕时间对应。字幕来自对齐结果，语音变化后不能继续使用旧固定秒数。
- `data-at` 或等价机制可以控制元素出现；标记词对应的时间应优先来自 `timing.json`。

内置模板只有显式 `?play=1` 的浏览器预览才自动播放。普通加载保持开场等待渲染器启动。

## 验证

在每句字幕中段、章节末尾和关键交互时刻抽帧。检查文字裁切、空白、对比度、遮挡、连线、鼠标位置与操作结果。自动溢出检查不能判断图的含义或艺术质量，保存的截图需要实际查看。

最终 MP4 必须实际解码和播放，再点章节跳转。对导出的音轨检查收尾，不能用“HTML 预览没问题”代替成片验证。
